# SparkLearn 3 分钟浏览器演示脚本

> 目标：从 `demo_user` 干净画像 v1 出发，展示 RAG 引用、真实答题评估、BKT 掌握度更新、错因画像、知识图谱解锁和路径重排。
>
> 本脚本已经按浏览器真实行为校准：每个题组会把 5 道题整组提交。临时干净 v1 数据库连续跑两次，结果完全一致：二叉树约 `100%`、高级排序约 `23%`、综合正确率 `60%`、做题闭环后画像 `v12`。

## 一、演示前检查

- 使用宽度不小于 `1024px` 的浏览器窗口，否则首页右侧“学生画像”会被 `hidden lg:block` 隐藏。
- 后端运行在 `http://127.0.0.1:8010`，前端运行在 `http://127.0.0.1:3000`。
- `demo_user` 基线应为：`PROFILE v1`、答题轮次 `0`、所有知识点掌握度 `30%`、错因为空。
- 资源库应保留 `128` 条 `demo_user` 资源；恢复操作不能删除资源或知识图谱。
- 目标题组位于资源页最近 50 条内：
  - `二叉树·智能习题组(5 题)`，资源 ID `d7115055f70b`
  - `高级排序·智能习题组(5 题)`，资源 ID `c8ff83c4ecd5`

## 二、3 分钟讲解词与点击顺序

### 0:00-0:45　RAG 防幻觉与引用溯源

1. 打开 [资源工坊](http://127.0.0.1:3000/resources)。
2. 知识点选择“二叉树”。
3. 资源类型只保留“图文教程”，取消“思维导图 / 智能题组 / 代码示例 / 讲解视频”。
4. 点击“生成 1 类资源”，等待本次生成结果出现。
5. 展开“二叉树·图文教程”：
   - 正文中应看到 `[^1]`、`[^2]` 一类脚注标记。
   - 卡片底部应看到 `CITATIONS · 引用来源` 和教材来源。

讲解词：

> 这里不是让大模型凭空写。Doc Agent 先从数据结构教材检索真实片段，再要求模型用 `[^n]` 标注事实来源，最后还会做答案与证据一致性检查。

注意：生成资源会先运行 Profile Agent。若模型从本次生成目标中抽取出合法画像字段，画像版本可能先增加 1。因此，“先现场生成文档，再要求最终版本严格为 v5”目前不能保证。

### 0:45-1:40　做题并更新掌握度

在“我的资源库”中找到 `二叉树·智能习题组(5 题)`。

按下面答案完成 5 题：

1. 选择 `C`。
2. 填写 `1`。
3. 选择“对”。
4. 填写 `O(n)`。
5. 填写一段正确思路，例如：`递归比较左右镜像节点，值相同且外侧、内侧子树都对称。`

点击“提交并更新掌握度”后应看到：

- 本组正确率：`100%`
- 二叉树掌握度：`30% → 99.96%`，页面四舍五入显示 `100%`
- 画像版本：干净 v1 起算时变为 `v6`

然后找到 `高级排序·智能习题组(5 题)`。

按“错、对、错、错、错”完成 5 题：

1. 故意选择 `A`（正确答案是 `D`）。
2. 填写 `O(n log n); 稳定`。
3. 故意选择“对”（正确答案是“错”）。
4. 故意填写 `O(1)`。
5. 故意填写 `不知道`。

点击“提交并更新掌握度”后应看到：

- 本组正确率：`20%`
- 高级排序掌握度：`30% → 23.25%`，页面显示 `23%`
- 画像最终保留的前三个错因：`边界条件 / 时间复杂度 / 算法稳定性`
- 画像版本：干净 v1、只计算这两轮答题时为 `v12`

这套答案已经在两份独立的临时干净 v1 数据库中通过现有 `/api/eval/submit` 重复验证，两次结果完全一致。

### 1:40-2:10　查看学情评估

打开 [学情评估](http://127.0.0.1:3000/eval)。

应看到：

- 累计答题轮次：`2`
- 综合正确率：`60%`
- 二叉树掌握度：约 `100%`
- 高级排序掌握度：约 `23%`
- 错因：`边界条件 / 时间复杂度 / 算法稳定性`

现场解释：

> 综合正确率按两组题的成绩平均：二叉树题组 100%，高级排序题组 20%，所以 `(100% + 20%) / 2 = 60%`。本次两组题刚好各有 5 题，因此也等于 10 题中答对 6 题。

### 2:10-2:40　查看知识图谱与动态路径

打开 [学习路径](http://127.0.0.1:3000/path)。

目标验收口径应看到：

- 二叉树达到约 `100%`，状态变为“已掌握”。
- `BST` 和“堆与优先队列”从“待解锁”变为“可学习”，进入推荐序列。
- 高级排序掌握度降至约 `23%`，节点优先级分数从约 `0.46` 上升到约 `0.53`；它仍受先修关系约束，不一定进入可学习队列。
- 推荐序列第 1 位仍是“复杂度分析”，第 2、3 位为 `BST`、`堆与优先队列`。

讲解词：

> 系统不是只改一个百分比。BKT 更新后，路径服务会读取同一份最新掌握度，再结合先修关系重新判断“已掌握、可学习、待解锁”和推荐顺序。

### 2:40-3:00　回首页展示画像变化

1. 打开 [学习对话首页](http://127.0.0.1:3000/)。
2. 保持宽屏，点击右侧“学生画像”。
3. 查看雷达图形状、薄弱知识点、错因和 `PROFILE vN`。

只计算两轮做题时，稳定口径是 `PROFILE v1 → v12`：

- 二叉树 5 道题逐题 BKT 更新：版本 `+5`
- 高级排序 5 道题逐题 BKT 更新：版本 `+5`
- 高级排序错因标签合并：版本 `+1`

若演示前现场生成文档时 Profile Agent 额外抽取到合法画像字段，做题前版本可能已经是 v2，最终会显示 v13。最稳妥的现场表述是：“两轮做题让画像版本增加 11，并且雷达图、错因和路径同步变化。”

## 三、空货架与引用预检结论

### 空货架

- 干净 v1 的第 1 推荐知识点：`complexity`（复杂度分析）。
- 做完真实 5+5 题后，第 1 推荐仍是 `complexity`；`BST` 和“堆与优先队列”进入第 2、3 位。
- `complexity` 不是空货架：当前有 `7` 条资源（1 文档、4 脑图、1 题组、1 视频）。

演示时可以点开的资源：

- `f975bab962cc`：复杂度分析脑图，内容和引用均来自复杂度、线性表教材；内容较短，优先展示。
- `785c65da5f26`：复杂度分析脑图，核心内容正确，但少数长叶子被截断；可以作为备选。

演示时必须避开的资源：

- `15266277becf`：混入“先来先服务 FCFS / 按到达顺序调度”。
- `7af9734c7d8c`：标题写复杂度，实际是二叉树题组。
- `8627b4dd6ade`：标题写复杂度，实际是二叉树脑图。
- `8a05c2d13135`：标题写复杂度，实际是二叉树与 BST 文档。
- `19ac81cf9797`：视频标题和旁白写复杂度，但内部 `manim_code` 实际是二叉树文档。

因此，若评委从路径页点击“复杂度分析”的“生成资源”，应现场新生成；若只是检查旧货架，只展开资源 ID `f975bab962cc`，不要随意展开其他同名卡片。

### 引用

- `doc_agent.py` 的 prompt 明确要求事实性表述使用 `[^n]`。
- 当前数据库中的二叉树讲解文档正文确实含 `[^1] / [^2]`，并带 1-2 条引用来源。
- 这属于“强提示 + 真实样本已验证”，不是后处理强制插入；现场生成后仍应肉眼确认脚注和引用区都出现。

## 四、干净 v1 恢复命令（只记录，未执行）

以下 PowerShell 命令只重置 `demo_user` 的画像、答题记录、事件和路径；不删除资源，不修改 `knowledge_graph.json`。执行前会把当前数据库备份到治理目录，并断言 `demo_user` 的资源数仍为 `128`。

```powershell
Set-Location "C:\Users\26054\Desktop\sparklearn-multiagent\backend"

$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
Copy-Item -LiteralPath ".\sparklearn.db" `
  -Destination ".\runs\profile-governance-20260625\sparklearn-before-browser-demo-$stamp.db"

@'
import json
from pathlib import Path

from app.models.db import session
from app.models.entities import EventLog, PathPlan, Profile, QuizAttempt, Resource

USER_ID = "demo_user"
snapshot_path = Path("runs/profile-governance-20260625/demo_user_reset_result.json")
snapshot = json.loads(snapshot_path.read_text(encoding="utf-8"))
clean_profile = snapshot["profile"]
clean_version = int(snapshot["profile_version"])
expected_resources = int(snapshot["remaining_resources"])

with session() as s:
    profile = s.get(Profile, USER_ID)
    if profile is None:
        raise RuntimeError("demo_user profile 不存在，停止恢复")

    resources_before = (
        s.query(Resource).filter(Resource.user_id == USER_ID).count()
    )
    if resources_before != expected_resources:
        raise RuntimeError(
            f"资源数异常：期望 {expected_resources}，实际 {resources_before}，停止恢复"
        )

    profile.data = clean_profile
    profile.version = clean_version
    s.query(QuizAttempt).filter(
        QuizAttempt.user_id == USER_ID
    ).delete(synchronize_session=False)
    s.query(EventLog).filter(
        EventLog.user_id == USER_ID
    ).delete(synchronize_session=False)
    s.query(PathPlan).filter(
        PathPlan.user_id == USER_ID
    ).delete(synchronize_session=False)
    s.commit()

with session() as s:
    profile = s.get(Profile, USER_ID)
    attempts = s.query(QuizAttempt).filter(QuizAttempt.user_id == USER_ID).count()
    events = s.query(EventLog).filter(EventLog.user_id == USER_ID).count()
    path_exists = s.get(PathPlan, USER_ID) is not None
    resources = s.query(Resource).filter(Resource.user_id == USER_ID).count()
    mastery = dict(profile.data or {}).get("knowledge_mastery", {})
    error_prone = dict(profile.data or {}).get("error_prone", [])

    assert profile.version == 1
    assert attempts == 0
    assert events == 0
    assert not path_exists
    assert resources == expected_resources
    assert all(float(value) == 0.3 for value in mastery.values())
    assert error_prone == []

    print({
        "profile_version": profile.version,
        "attempts": attempts,
        "events": events,
        "path_exists": path_exists,
        "resources": resources,
        "mastery_all_0_3": True,
        "error_prone": error_prone,
    })
'@ | .\.venv\Scripts\python.exe -
```
